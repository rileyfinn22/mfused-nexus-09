- Global search: one security-definer RPC `global_search` (staff-only, word-by-word ILIKE across records) feeds the header search bar shown only to VibePKG staff; page searches use `src/lib/plainSearch.ts` matchesQuery so typed words must match word-starts in the order typed (first word gates the rest). Why: one consistent plain-language match everywhere, no customer data leakage.
- Order editor, detail edits and draft autosave use staff-only SECURITY INVOKER save_order_lines with existing RLS: preserve line IDs and write/reorder/delete in one transaction; verify counts and refuse processing empty or unsaved orders. Why: unique sequence conflicts and failed replacements must roll back without deleting saved products.
- Stale tabs: UpdateAvailableBanner compares the loaded /assets/index-*.js with the served index.html and asks users to reload. Why: tabs opened before a deploy keep running old save code.
- Product-to-template conversion uses the staff-only SECURITY INVOKER convert_product_to_template transaction, locks the product and retains its ID and SKU; repeat calls return the existing template. Why: adding variants must not orphan artwork or historical order/invoice references or leave half-created templates.
- Credit-card payments on invoices are controlled by the CARD_PAYMENT_COMPANY_IDS allowlist in supabase/functions/quickbooks-sync-invoice (currently Best 365 and Borealis); syncing or refreshing a payment link sets AllowOnlineCreditCardPayment for those companies only. Why: card acceptance is enabled per customer, not portal-wide.
