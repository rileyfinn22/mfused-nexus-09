- Global search: one security-definer RPC `global_search` (staff-only, word-by-word ILIKE across records) feeds the header search bar shown only to VibePKG staff; page searches use `src/lib/plainSearch.ts` matchesQuery so typed words must match word-starts in the order typed (first word gates the rest). Why: one consistent plain-language match everywhere, no customer data leakage.
- Order editor, detail edits and draft autosave use staff-only SECURITY INVOKER save_order_lines with existing RLS: preserve line IDs and write/reorder/delete in one transaction; verify counts and refuse processing empty or unsaved orders. Why: unique sequence conflicts and failed replacements must roll back without deleting saved products.
- Stale tabs: UpdateAvailableBanner compares the loaded /assets/index-*.js with the served index.html and asks users to reload. Why: tabs opened before a deploy keep running old save code.
- Product-to-template conversion uses the staff-only SECURITY INVOKER convert_product_to_template transaction, locks the product and retains its ID and SKU; repeat calls return the existing template. Why: adding variants must not orphan artwork or historical order/invoice references or leave half-created templates.
- Credit-card payments on invoices are controlled by the CARD_PAYMENT_COMPANY_IDS allowlist in supabase/functions/quickbooks-sync-invoice (currently Best 365 and Borealis); syncing or refreshing a payment link sets AllowOnlineCreditCardPayment for those companies only. Why: card acceptance is enabled per customer, not portal-wide.
- CompanyProvider owns session-driven company loading: defer queries outside auth callbacks, deduplicate same-user events, and ignore stale responses; Login relies on this readiness and DashboardLayout owns role redirects. Why: prevent auth-lock stalls, repeated requests, and login redirect races without changing permissions.
- Auth clock-skew fix: src/lib/authClockFix.ts (first import in main.tsx) wraps fetch and re-bases auth session expires_at to device time (now + expires_in). Why: devices with a wrong clock otherwise loop on token refresh, get rate limited, and are sent back to login.
- SKU changes on Edit Product go through the staff-only SECURITY INVOKER rekey_product_sku RPC: one transaction, scoped to the product's company, refuses duplicate SKUs, re-keys artwork_files + rejected_artwork_files. Why: the old inline re-link updated artwork by SKU across all companies and could orphan or hijack another company's art.
- Proof-ready customer emails go through the send-proof-notification edge function (vibe_admin only, recipients resolved server-side from user_roles); products.proof_notified_at records the last send. Why: the browser passes only a product id so recipients/content cannot be spoofed.
- Invoice and order-confirmation PDF renderers sort a copy of rows by saved line_number, nulls last. Why: downloads must not depend on unordered query results or mutate the editor's row sequence.
- EmailPreviewDialog resolves saved and pending typed recipients through emailRecipients before submission. Why: sending must not require an extra Add/Enter step and invalid typed addresses must block submission.
- Order editor inserts a blank order_number for the shared database trigger to allocate; next_order_number serializes allocation and excludes timestamp-sized numbers, and the trigger replaces oversized numbers from stale clients. Why: malformed identifiers must not poison the counter or race with customer submissions.
- Invoice recalculation on order_items updates must include shipped_quantity alongside quantity, unit_price and order_id; reuse recalc_blanket_invoices_for_order without duplicating its rules. Why: shipped-only edits must update invoice totals and mark changed QuickBooks invoices pending instead of leaving subtotal drift.
